# 工作流设计思想：从执行层到设计层的跃迁

用户在前 9 课掌握了所有执行层机制（T-P-G、调度、Context Engineering、五步闭环、MCP、Hooks、缓存），但明确表示想要的是「设计思想」而非「设计方法」。这是从「会用工具」到「会设计」的关键跳跃。

第 10 课建立了三个核心思维工具：
1. **HTA（层级任务分解）**：递归地把复杂任务拆到「AI 不会做错」的粒度
2. **六种工作流设计模式**：Pipeline / Routing / Fan-out / Orchestrator / Evaluator-Optimizer / Human-in-the-Loop
3. **五层设计思维流程**：分解 → 选模式 → 加护栏 → 定边界 → 补不可见步骤

核心洞察：分解决定了 80% 的设计质量。分解对了，prompt 可以很简单。分解错了，护栏也救不回来。Workflow 设计的本质不是写 prompt，是设计问题的分解结构。

## Evidence
- 用户明确表达了「关键的在于设计思想」——这是对前 9 课「工具层」学习的自然升华
- 用户已从零设计过完整 Skill（study-note、feynman-test），具备将抽象模式映射到具体经验的基础

## Implications
- 下一课（综合实战）应该让学生主导设计决策，老师退后为「设计评审者」角色
- 学生现在有能力回答「为什么拆成这几步而不是那几步」——这是设计思维的标志
- HTA + 六模式可以作为今后所有 skill 设计的标准起点
