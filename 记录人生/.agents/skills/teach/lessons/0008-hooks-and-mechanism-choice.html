第 8 课：Hooks — 规则机械化的最后一环

Skill 说「应该做」，Hook 说「不这么做就过不去」

📅 2026-06-14 ⏱ ~20 分钟 ← 第 7 课

1. 一个场景开头

你的 study-note skill 第 4 步 checklist 里有一条：

- [ ] 无敏感信息（密码/密钥/Token）

这是 Skill 层的约束——AI 在写入之前应该检查。但 AI 可能漏查、可能误判、可能跳过。这是「建议层」的防护。

如果这是你的公司代码仓库，HR 政策要求密码绝对不能进 Git——你会只靠 AI 自觉吗？

不会。你会用 Hook。

Skill 约束 = AI 应该做（软约束，可能漏）
Hook 约束 = 代码强制执行（硬约束，不会漏）

2. Hooks 是什么

Hook 是在 Agent 生命周期的特定节点自动触发的 shell 命令。它在 AI 行动之前或之后在代码层面介入，不受 AI 的「判断」影响。

SessionStart │ ▼ 用户发消息 ──→ UserPromptSubmit │ ▼ AI 准备调用工具 ──→ PreToolUse ← 可以拦截/修改/确认 │ ▼ 工具执行 │ ▼ 工具执行完毕 ──→ PostToolUse ← 可以检查结果/记录日志 │ ▼ AI 回复用户 │ ▼ SessionEnd / Stop

每个 Hook 收到一个 JSON（含当前事件、工具名、参数等），返回 exit code 决定行为：

exit code含义
0放行，正常继续
2阻止，并显示 stderr 给 AI
stdout 输出 JSON修改行为（如替换参数、注入上下文）

3. 三种机制的分工

Claude Code 有三种扩展机制。它们不是竞争关系，是不同层面的控制：

Skill

AI 读到了什么
→ 上下文层

告诉 AI 该怎么做
AI 可以选择不遵守

Hook

AI 被拦截了什么
→ 执行层

强制执行规则
AI 没有选择权

MCP

AI 能调用什么
→ 能力层

扩展 AI 的工具箱
AI 可以选择用不用

机制回答的问题可靠性AI 能绕过吗
Skill 「AI 应该怎么做？」 中等 — 取决于 AI 遵守指令的程度 能 — AI 可以忽略 skill 指令
Hook 「什么绝对不允许？」 极高 — 代码强制执行 不能 — 在工具层拦截
MCP 「AI 能做什么？」 高 — 工具逻辑是确定性的 能 — AI 可以选择不调用
三者关系：Skill 管流程，Hook 管底线，MCP 管能力。一个完整的 Agent 系统同时需要三者。

4. Hooks 能做什么

场景Hook 事件怎么做
🚫 禁止写入敏感文件 PreToolUse (Write) 检查路径，匹配到 /etc/、.env → exit 2
🔍 写入前扫描密钥 PreToolUse (Write) 用 regex 扫描文件内容，匹配到疑似密钥 → exit 2 + 提示
📝 自动格式化输出 PostToolUse (Write) 写入后自动运行 prettier/black 格式化
📊 操作日志 PostToolUse (*) 每次工具调用后记录到审计日志
⚠️ 危险操作需确认 PreToolUse (Bash/Delete) 匹配危险命令（rm -rf、git push --force），要求用户确认
📎 注入项目上下文 UserPromptSubmit 在用户消息前自动附加项目规范或状态信息

5. 实战示例：Write Hook 防密钥泄露

// .claude/settings.local.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write",
        "command": "python H:/scripts/check-secrets.py"
      }
    ]
  }
}
# check-secrets.py（被 Hook 调用，从 stdin 读 JSON）
import json, sys, re

SECRET_PATTERN = re.compile(
    r'(password|secret|token|key|api_key)\s*[:=]\s*[\'"][^\'"]{8,}[\'"]',
    re.IGNORECASE
)

data = json.load(sys.stdin)
content = data.get("tool_input", {}).get("content", "")

if SECRET_PATTERN.search(content):
    print("BLOCKED: 疑似密钥/密码，禁止写入", file=sys.stderr)
    sys.exit(2)  # ← 阻止写入

sys.exit(0)  # ← 放行

这个 Hook 比 skill 里的 checklist 强在哪？AI 可以跳过 checklist，但不能跳过 Hook。

6. 决策框架：什么时候用哪个？

核心问题：这条规则失败时，后果有多严重？
后果用什么为什么
可接受（格式有点丑、步骤顺序不太对） Skill 软约束足够，下次用第 5 课的闭环迭代改进
不好但能补救（查错了信息、引用了不存在的文件） Skill + G 护栏 在 skill 中加强 Guardrails，加入兜底策略
不可接受（泄露密码、删除关键文件、推送未审查代码） Hook 必须用 Hook，软约束不可靠
AI 缺少某种能力（查数据库、调内网 API） MCP 给 AI 新工具，让它能做到以前做不到的事

7. Skill + Hook 配合：同一条规则的软硬两面包

以「不写入密码」为例，最佳实践是双层防护：

┌─────────────────────────────────────────┐
│ Skill 层：                                │
│ 「写入前检查：无敏感信息（密码/密钥/Token）」│  ← 告诉 AI
│                                          │
│ +                                        │
│                                          │
│ Hook 层：                                 │
│ PreToolUse(Write) → check-secrets.py     │  ← 强制拦截
│ 检测到密码 → exit 2 → 阻止               │
└─────────────────────────────────────────┘

Skill 是最佳努力（best effort），Hook 是最终防线（last line of defense）。两者不是替代关系——是互补。

8. 回到你的 Harness Engineering 笔记

你在第 1 课前就记下了这 6 条原则，其中第 4 条是：

「规则不要只写在文档里，能机械化就机械化。」

现在你知道这句话在工程上的含义：

  • 「写在文档里」= 放在 Skill 或 CLAUDE.md 里 → AI 应该遵守
  • 「机械化」= 写成 Hook → 代码强制执行，AI 绕不过去

Hook 就是「机械化」的实现手段。

9. 关键收获

本课核心：
1. Hook = 生命周期节点的强制 shell 命令，在工具层拦截，AI 绕不过
2. Skill = 上下文层，Hook = 执行层，MCP = 能力层——三层互补
3. 决策标准 = 后果严重度——能容忍的用 Skill，不能容忍的加 Hook
4. 最佳实践：Skill + Hook 双层防护——Skill 尽力而为，Hook 兜底
