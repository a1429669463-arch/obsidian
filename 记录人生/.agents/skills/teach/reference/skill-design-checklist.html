📋 Skill 设计检查清单

用 T-P-G 三角快速诊断任何 skill · 搭配 第 1 课 使用

T Trigger Precision 触发精度

#检查项判断标准
T1触发条件是否具体？包含具体的用户意图描述词（如「学习」「检验」），而非笼统的「用户需要帮助时」
T2触发特异性是否足够防误触发？用了什么机制？4 种机制之一：(1)窄描述 (2)disable-model-invocation (3)领域专有词汇 (4)显式排除条件。不要求一定有(4)。
T3和其他 skill 的触发条件无歧义重叠？两个 skill 不会同时匹配同一条用户请求（或明确写了优先级）
T4用户不精确表达时仍能触发？覆盖了常见变体说法（如用户不说「费曼」但说「考考我」）

P Procedure Clarity 流程清晰度

#检查项判断标准
P1每一步是否只有一个明确动作？不能「搜索并分析并整理」——拆成独立子步骤
P2动词是否可执行？用具体工具/操作（Grep、Write、AskUserQuestion）替代模糊动词（分析、处理、整理）
P3每步的输入和输出是否明确？上一步的输出 = 下一步的输入，中间没有「AI 自己看着办」的黑箱
P4决策分支是否有明确条件？「如果 X 则做 Y，否则做 Z」——条件不是 AI 自行判断，而是客观可验证的
P5引用外部文档时，指向是否精确？「读 references/note-rules.md 第 3 节」优于「参考参考资料」

G Guardrails 护栏完整度

#检查项判断标准
G1有没有绝对禁止的操作？「永远不要 X」「不得 Y」——硬约束，不可逾越
G2信息/工具不足时怎么办？明确写了兜底行为：问用户？跳过？标记待确认？
G3步骤失败时如何恢复？有重试策略或降级方案（如「搜索无结果 → 换关键词再搜一次 → 仍无结果则告知用户」）
G4有没有输出格式约束？明确规定了输出结构、格式、必须包含和不能包含的内容
G5有没有用户确认节点？不可逆操作（写入文件、修改配置）之前有用户确认步骤

快速诊断口诀

触发要精准——该来的来，不该来的别来
动作要原子——一步一动作，动词可执行
护栏要兜底——最蠢的情况也有预案
输出要明确——AI 知道「做到哪里算完」
