## 执行流程

### 第 0 步：检查已有笔记

先搜索知识库中是否已有相关笔记：

- 用 Grep 按概念关键词搜索 `**/*.md`
- 已有相关笔记 → 告知用户，询问是补充还是新建
- 无相关笔记 → 继续下一步

### 第 1 步：搜索获取知识

针对用户问题，通过网络搜索获取知识。规则见 `references/note-rules.md`。

### 第 2 步：规划文件

根据搜索结果规划笔记结构：

- 先确定一个**主概念文件**
- 如果发现值得独立展开的子概念，**建议**拆分（展现建议，等用户确认）
- 不要自动拆分——默认主概念成文，必要时才提议拆分

### 第 3 步：确认与创建

- **单文件**：告诉用户「我将创建 `路径/文件名.md`」，直接创建
- **多文件 / MOC / 移动文件**：必须列出完整清单，等用户确认后再操作
- 不得自动修改已有 MOC，除非用户明确要求

### 第 4 步：写入文件

读取`templates/note-template.md`，掌握输出要求，读 `references/note-rules.md` ,掌握详细规则

**写入前必须逐项确认（检查清单）：**

- [ ] frontmatter 有 `date` 和 `tags`（两者均必填）
- [ ] 有 `## 参考文献` 节，含至少 1 个 `[标题](URL)` 格式链接
- [ ] 有 `## 相关笔记` 节，含至少 1 个 `[[wikilink]]`
- [ ] 文件名符合 `<英文>-<中文>.md` 格式
- [ ] 开头一句话定义（概念名 + 英文名 + 定义）
- [ ] 无敏感信息（密码/密钥/Token）

全部打勾后再写入文件。

### 第 5 步：验证

文件写入后逐项检查：

1. 文件路径是否正确（目录存在、文件名符合规范）
2. frontmatter 是否完整（date、tags）
3. [[wikilink]] 指向的文件是否存在（不存在则标出）
4. 无密码/密钥/Token 等敏感信息

将验证结果告知用户。
