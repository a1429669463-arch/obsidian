# 笔记规则详解

## 必填项

以下内容**每篇笔记缺一不可**，写入前对照检查：

| 必填项 | 位置 | 格式 |
|--------|------|------|
| `date` | frontmatter | `YYYY-MM-DD` |
| `tags` | frontmatter | 至少 1 个标签 |
| `## 参考文献` | 正文末 | 至少 1 个 `- [标题](URL)` |
| `## 相关笔记` | 正文末 | 至少 1 个 `[[wikilink]]` |

## 来源标注

每篇笔记应有 **1-3 个可靠来源**，关键结论必须有来源支撑。

优先级：官方文档 > 维基百科 > 权威技术博客 > 其他

- 来源放在「参考文献」节，格式：`- [来源标题](URL)`
- 完全来自 AI 训练知识、搜索不到来源 → 行尾或来源后标注 `<!-- 待确认 -->`
- 来源部分确认但非完全 → 说明：`- [来源](URL) — XX 部分待验证`
- 多个来源矛盾 → 增「⚠️ 存在争议」节，列出各方说法及各自来源

## 不确定信息标记

以下情况必须标注「待确认」：

1. AI 基于训练数据的推断，无公开可验证来源
2. 来源本身标注了「传言」「据称」「未经证实」
3. 不同来源的数据/说法互相矛盾
4. 信息可能已过时（技术类超过 2 年）

标注方式：
- 整段不确定 → 段尾加 `（待确认）`
- 单条来源不确定 → 参考文献中加 `<!-- 待确认 -->`
- 存在矛盾 → 增「⚠️ 存在争议」小节

## 原子化原则

**默认一个概念一个文件**，但不强制拆分。判断逻辑：

- 先围绕主概念写 —— 子概念在主文件中用一两句话说清
- 只有当子概念满足以下条件时才**建议**拆分：
  - 可被其他笔记独立引用
  - 有独立的「定义 + 解释」结构
  - 需要独立的参考文献列表
- 三两句话能讲清的补充信息 → 留在主文件，不拆分

## 文件命名

格式：`<英文缩写>-<中文概念名>.md`

- 如 `LLM-大语言模型.md`、`Token-词元.md`
- 无通用英文缩写 → 只用中文
- 文件名表意，避免「无标题」「新笔记」

## 文件放置

- 默认：`00收件箱/`
- 用户明确指定领域 → 对应 Area 子目录（如 `Area/IT相关/AI/基础概念/`）
- 创建后告知用户文件位置

## MOC 规则

- **禁止自动修改 MOC 文件**，除非用户明确要求
- 如需添加链接到 MOC，提示用户手动添加或请用户确认

## 安全注意

- 密码、密钥、Token 等敏感信息不得以纯文本写入笔记
- 遵循 `HOME.md` 中已有的笔记规范
