# 缓存命中率：前缀匹配机制与 Context Engineering 的财务回报

用户主动询问如何提高缓存命中率。这是 Context Engineering（第 4 课）的直接延伸——缓存的「静态在前，动态在后」原则与上下文设计的信息分层完全对应。

核心理解：
- 缓存 = 前缀匹配，前缀任何位置改变 → 之后全部失效
- 四层结构：系统提示+工具 → 项目上下文 → 会话上下文 → 对话消息
- 8 个缓存杀手：切换模型、改 effort、MCP 变动、compact、升级、deny 工具、插件 MCP、fast mode
- Skill 天然缓存安全（指令以用户消息追加）
- 缓存命中率是上下文结构的质量指标——高命中 = 结构好

用户已在第 4 课学会信息密度公式和预算测试，本课将这些工具翻译到缓存维度。
