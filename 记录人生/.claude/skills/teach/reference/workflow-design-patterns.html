六种基础模式

Pipeline 链式管道

何时用：任务有天然先后依赖。上一步输出 = 下一步输入。

[A] → [gate] → [B] → [gate] → [C]

你的例子：study-note 的 搜索→规划→写入→检查。

Routing 路由分流

何时用：同一入口，不同意图，需要不同处理。分类必须可靠。

输入 ─┬→ 类型A → 处理A ├→ 类型B → 处理B └→ 类型C → 处理C

你的例子：「学习XX」→ study-note，「考考我」→ feynman-test。

Fan-out 并行扇出

何时用：子任务之间无依赖，可同时进行。结果汇总。

┌→ [A] ─┐ 起点 ─┼→ [B] ─┼→ 汇总 → 输出 └→ [C] ─┘

两种变体：Sectioning（各做各的）/ Voting（同一任务多票）。

Orchestrator 编排-工人

何时用：任务复杂到无法事先规划所有子步骤，需动态分解。

Orchestrator: 分析 → 分解 → 分配 ├→ Worker 1（动态确定的子任务） ├→ Worker 2（动态确定的子任务） └→ Worker N Orchestrator: 合成 → 输出

与 Fan-out 区别：子任务是运行时动态决定的，不是预先列好的。

Eval-Opt 评估-优化

何时用：有明确可验证的质量标准。可自动评估时效果最好。

生成 → 评估 → 不通过？→ 带着反馈重新生成 → 通过？ → 输出

你的例子：study-note 第 5 步对照 checklist 检查 = 手动版 E-O。

Human-in-Loop 人机回路

何时用：后果不可逆、AI 置信度低、或需要人的偏好做决策。

AI 规划 → [等待确认] → AI 执行 → [等待确认] → 继续

本质：不是在加确认步骤，是在设计信任边界。

通用设计原则

一步一动作 — 每步只做一件事，有明确 I/O
原子性 — 要么完整成功，要么完整失败
显式 I/O — 上一步输出 = 下一步输入，不靠推断
幂等性 — 重试不会产生副作用
Fail-safe 默认 — 出错时停下来问，不猜
不可见步骤 — 人自动跳过但 AI 不会的步骤要显式写

设计思维流程（5 层）

第 1 层：分解（HTA） → 「这个任务从开始到结束，要经历哪几个阶段？」 → 画出 3-7 个顶层步骤 第 2 层：选模式（6 Patterns） → 「每一步之间是什么关系？顺序？并行？分支？循环？」 第 3 层：加护栏（Guardrails） → 「每一步最蠢的失败方式是什么？拦住了吗？」 第 4 层：定边界（Trust Boundary） → 「哪些决定 AI 自己做？哪些必须问人？」 第 5 层：补不可见步骤 → 「我自己做这件事时，做了哪些没意识到的判断？」
