第 1 课：本地改了文件，如何不让 Git 跟踪

文件管理 场景驱动 约 20 分钟

你有没有过这种时刻——

真实场景：项目里有个配置文件（比如数据库连接、本地端口号），你为了在本地跑起来改了几行，但不想把这个改动提交到仓库里。每次 git status 都看到它红彤彤地躺在那里，烦人又危险，怕手滑 git add . 把它也带上去了。

这个问题分两种情况，解法完全不同。让我们先分清楚你面对的是哪一种。

快速判断：你的文件属于哪种情况？

情况判断方式文件状态解法
A. 从未跟踪 git status 显示为 "Untracked files" Git 根本不认识这个文件 .gitignore
B. 已在跟踪 git status 显示为 "modified: xxx" Git 已经在版本库中记录了这个文件 git update-index --skip-worktree

跑一下 git status 看看你的文件在哪一栏，然后跳到对应章节。

情况 A：文件从未被跟踪 → .gitignore

如果你看到的文件名在 Untracked files: 下面，恭喜你，这是最简单的场景。

# 把文件名或模式写入 .gitignore
echo "config.local.js" >> .gitignore

# .gitignore 本身需要提交，这是项目的公共规则
git add .gitignore
git commit -m "忽略本地配置文件"
常见误区：.gitignore 只对 从未被跟踪过的文件 生效。如果文件已经被 Git 跟踪了（情况 B），写到 .gitignore 里完全不管用。这也是为什么很多人搜答案搜到 .gitignore 然后发现没有效果——他们的文件已经被跟踪了。

情况 B：文件已在跟踪 → skip-worktree

如果文件已经在 Git 的版本库里了（你或别人之前提交过它），你需要的是 --skip-worktree。

# 告诉 Git：「这个文件我本地可能会改，你别管它」
git update-index --skip-worktree <文件名>

# 效果：git status 不会再显示它的修改
# 你的本地修改不会被 git add / git reset --hard 意外带走

以后想恢复跟踪：

git update-index --no-skip-worktree <文件名>

查看当前有哪些文件被标记了：

git ls-files -v | grep '^S'
# S = skip-worktree（你打的标记）
# h = assume-unchanged（另一种标记，见下文）

那 --assume-unchanged 呢？

你可能在搜索时也看到过 --assume-unchanged。两者的区别：

--assume-unchanged--skip-worktree ✅
设计目的性能优化（跳过慢文件系统的检查）真正忽略本地修改
git status 不显示修改✅✅
git reset --hard❌ 会覆盖你的本地修改✅ 不会覆盖
切换分支❌ 可能报错阻止切换✅ 平滑切换
结论：想忽略本地修改 → 用 --skip-worktree，忘了 assume-unchanged 吧。后者是给文件系统慢的大型仓库做性能优化的，不是用来"忽略修改"的。

情况 B 的变体：我想彻底停止跟踪，但保留本地文件

如果你不仅想忽略本地修改，还想让 Git 从此彻底不再跟踪这个文件（但磁盘上保留它）：

# 从 Git 索引中移除，但保留本地文件
git rm --cached <文件名>

# 然后加到 .gitignore，确保以后不会再被跟踪
echo "<文件名>" >> .gitignore

# 提交这个"取消跟踪"操作
git commit -m "停止跟踪 <文件名>"

之后其他人在 pull 这次提交时，文件会从他们的 Git 跟踪中移除，但注意——他们本地的文件副本也会被删掉。团队协作时慎用，提前沟通。

场景决策树


git status 看到文件改了，不想提交
│
├─ 文件在 "Untracked files" 下？
│   └─ 是 → 写入 .gitignore
│
├─ 文件在 "modified:" 下？
│   ├─ 短期内都要忽略 → git update-index --skip-worktree <file>
│   └─ 永久停止跟踪       → git rm --cached <file> + 写入 .gitignore
│
└─ 你只想这次 commit 不包含它，下次还正常跟踪
    └─ git add <具体文件> 而不要用 git add .  (这是选文件提交，不是忽略)

动手练习

练习 1：判断场景

你的项目有一个 db.config.json，它从项目一开始就在仓库里。现在你在本地改了数据库端口号以便调试，但不希望这个改动被 Git 跟踪或意外提交。应该用什么命令？

练习 2：补充命令

你想查看当前仓库里有哪些文件被 skip-worktree 标记了，命令是：

git ls-files _____ | grep '^S'

横线处应该填什么？在终端里试试看。

练习 3：真实操作

在你的 Git 仓库（比如当前的 Obsidian vault）中，找一个已经被跟踪的文件，执行：

  1. git update-index --skip-worktree <文件>
  2. 修改它
  3. 跑 git status 验证修改不显示
  4. 用 git ls-files -v | grep '^S' 确认标记
  5. 执行 git update-index --no-skip-worktree <文件> 恢复
  6. 再跑 git status 确认修改重新可见

做完后在终端里确认每一步的效果。

本节要点

  • .gitignore 只对 未跟踪文件 生效，已跟踪文件加了也没用
  • 已跟踪文件想忽略本地修改 → git update-index --skip-worktree <file>
  • 永久停止跟踪但保留本地文件 → git rm --cached <file> + .gitignore
  • 用 git ls-files -v | grep '^S' 查看所有被标记的文件
